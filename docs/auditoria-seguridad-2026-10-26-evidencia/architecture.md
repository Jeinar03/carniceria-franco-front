# Arquitectura - carniceria-franco-front (run-1)

1. Producto y principales. SPA Angular 14 de la tienda en linea Carniceria Franco (marca visible "Franko"). Principales: visitante anonimo (catalogo, categorias, contacto, alertas del sitio, configuracion del sitio), cliente registrado (login/registro, carrito, checkout con Mercado Pago / transferencia / efectivo, historial de compras, perfil, fotos de seguimiento, encuesta de satisfaccion), operador/admin (usa un panel admin separado en el backend Laravel, no en este repo). Recursos protegidos: token Sanctum del cliente, datos personales (nombre, correo, telefono, direccion, saldo, descuento preferencial), ventas/pedidos, precios y montos cobrados, datos bancarios de la tienda, fotos subidas por el cliente.

2. Comparable: tienda SPA tipica que delega toda autorizacion a una API REST con bearer token; el patron aceptado es que el front no es frontera de seguridad. Se usa solo para calibrar.

3. Stack y despliegue visibles. Angular 14 + RxJS + ngx-toastr + Bootstrap; jQuery 3.4.1, bootstrap 5.0.0 bundle y owl carousel cargados por <script> desde CDNs en src/index.html. Tres modos de despliegue en el repo: (a) build estatico con src/.htaccess (Apache/Hostinger) - apiUrl de produccion https://carniceriafrancoadmin.shop/api/v1 en src/environments/environment.prod.ts; (b) vercel.json con rewrite /api/v1/* hacia un Heroku (infinity-api-app-...herokuapp.com); (c) server.js Express (Procfile, Heroku) que sirve dist/onvert-theme (nombre distinto de outputPath dist/convert-theme en angular.json). Backend Laravel (repo carniceria-franco-backend) NO esta en este objetivo: toda decision de autorizacion, precio, descuento, stock y estado de pago ocurre ahi y no es visible. No hay node_modules: no se puede compilar ni ejecutar la app; solo arneses minimos en Node 22 dentro del sandbox.

4. Superficies de entrada y caminos. Respuestas de la API (productos, categorias, sitio/config con redes y datos bancarios, sitio/alertas con link_url e imagen_url, ventas, recomendaciones) -> plantillas Angular (interpolacion, [src], [href]) y window.location.href (init_point de Mercado Pago, src/app/public/pages/carrito/carrito.component.ts:369). Query params (payment-callback: payment_id, status; perfil: tab). localStorage (token, clienteId, clienteDescuentoPreferencial, clienteSaldo, carrito_franco con precios del producto, image, profileIsComplete) -> guardias, interceptor, cuerpos de peticion (customer_id, productos, cantidad, monto_pesos) y URLs (/ventas/cliente/{id}, /usuarios/update/{id}, /usuarios/store-images/{id}, /usuarios/borrar/{id}/imagenes/{img}, /indicadores/pedidos/{sale}/preguntas?customer_id). Formularios de login/registro. Subida de archivos (evidencia de transferencia, imagenes base64 de seguimiento). Historial git (secretos borrados).

5. Fronteras y control visible mas fuerte. Navegador -> API: AuthInterceptor (src/interceptors/auth.interceptor.ts) adjunta Bearer solo si la URL empieza con environment.apiUrl; 401 -> logout. Rutas: AuthGuard (src/guards/auth/auth.guard.ts) solo verifica que exista 'token' en localStorage (control solo de UX). Precios/descuentos: el carrito ya no manda descuento (commit 922d086) pero manda customer_id, cantidad y monto_pesos; el servidor debe recalcular. Pago: payment-callback llama confirm-payment y dice no confiar en la URL. Render: sanitizacion por defecto de Angular (sin innerHTML ni bypassSecurityTrust en src/app segun grep). Despliegue: .htaccess solo define rewrite SPA y no-cache de index.html; no hay CSP, X-Frame-Options ni SRI visibles.
